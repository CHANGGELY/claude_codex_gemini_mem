# 开发工作流 (Development Workflow)

## 核心原则
- **测试驱动开发 (TDD)**: 在实现功能之前编写测试。
- **任务原子化**: 将大型功能拆分为小的、可验证的任务。
- **持续验证**: 每个任务完成后运行构建和测试。

## 质量标准
- **测试覆盖率**: 核心逻辑的测试覆盖率必须保持在 **80%** 以上。
- **类型安全**: TypeScript 代码必须通过严格的类型检查。
- **代码风格**: 必须符合 `conductor/code_styleguides/` 中定义的规范。

## 提交与记录协议
- **频率**: 在完成每个任务（Task）后进行 Git 提交。
- **任务摘要**: 使用 `git notes` 记录每个任务的技术决策和变更摘要。
- **提交信息**: 遵循约定式提交规范 (Conventional Commits)。

## 阶段完成验证协议 (Phase Completion)
在每个阶段（Phase）结束时，必须执行以下操作：
1. 运行完整的测试套件。
2. 运行构建命令确保无编译错误。
3. 执行：`- [ ] 任务: Conductor - 用户手册验证 (按此协议执行)`
